==============About the project===============
Build a key-value REST API
- Code a key-value API to store information under specific keys.
- Run multiple containers for the application & database.
- Leverage volumes to persist data from the database container.
- Connect database & application container by leveraging user-defined networks.
- Use shell script to manage the creation of containers, networks & volumes.

? API Specifications: API method & path -> Expected behaviour
POST /store
- Expects requests body to contain both "key" & "value"
- Returns 400 if this is not the case.
- if the key already exists in DB, return 400.
- if the key does not exist,stores key & value and, returns 201.
GET /store/:key
- if the key does not exist, return 404.
- if the key exist,returns 200 with both key & value.
PUT /store/:key
- Expects requests body to contain "value"
- Returns 400 if this is not the case.
- if the key does not exist, returns 404.
- if the key exists, update the value and return 200.
DELETE /store/:key
- if the key does not exist, return 404.
- if the key exists, delete the key & returns 204.
GET /health
- Returns 200 and the text "up"

01. Running a MongoDB server as docker container
- Use community-server, Version 7.0.22-ubuntu2204, name container name as "mongodb"
- Check container is UP & no error in starting database
- Connect to instance, switch to admin db and see the collection in it.
- Stop the container and remove.
02. Adding root credential to Mongodb server, during docker creation, so that default user cannot see any objects.
- create a shellscript "start-db.sh"
    - include the docker command
    - parametrize all,
    - include root user/password as environment value
    - check you are able to login as root password.
03. Create user inside key-value database, during initialization of docker.
- Create a folder "db-config" and create a script "mongo-init.js"
    - Update the js file to create user and assign "readWriteRole" role to database ""
    - include the script as volume in specific folder.

    - Define a network name in docker command

- Create another conatainer and connect to the mongodb server using argument.

11. Creating and getting Key Value pair
- Mongose to create a schema and create a model based on that.
    - Several collection get created once you create the model in background.
    - create a keyvalue.js under src/model
- import in stores.js
    - Define the post route for /store
        - accept request body key, value and try catch error.
            - if any one missing return 404
        - check if key already exists, the 400
            - update the key/value and resturn 201
    - Define the get route for /store/:key
        - accept request param key and try catch error.
        - Check the key exists, if exists return the key & value
12. Updating and deleting Key Value pair
- Define the put route for /store/:key
    - get the key from param & value from body
        - if value missing return 404
    - update the key with the value
        - if no update return 400
        - otherwise 200
- Define the delete route for /store/:key
    - get the key from param
    - if the key doesn't exist return 400
    - If exists remove the entry and return 204.
