- Where it is useful

- Imperative approach tells kubernetes "what to do"
- Config file can be stored in version control(like git) providing a reviewable audit trail and a template for creating new object.
- Declarative approach tells kubernetes the desired end state. leaving it up to kubernetes to figure out the necessary action to get there.
- The drawback of imperatibe objectmanagement with configuration file approach is that it does not handles merging changes well. Kubectl replace expects a full object definition and if other controllers have modified the live object(by adding annotation) those changes can be accidentally wiped out.
